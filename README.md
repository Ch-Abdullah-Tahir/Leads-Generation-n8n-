# Leads Generation

A minimal React + Vite app with Supabase-backed sign up / login and a home page
for booking available time slots.

## One-time setup

1. **Create the database tables.** In your Supabase project dashboard, open
   **SQL Editor → New query**, paste the contents of
   [`supabase/schema.sql`](supabase/schema.sql), and click **Run**. This
   creates the `users` table (lead details) and `time_slots` table, their
   security policies. Slots are generated by n8n, not seeded in SQL.
   Then run `supabase/booking-limits.sql` to enforce the booking limit.
2. **(Optional) Skip email confirmation.** By default Supabase requires
   users to confirm their email before they can sign in. For quicker local
   testing, go to **Authentication → Providers → Email** and turn off
   "Confirm email". Leave it on for a real production flow.

Copy `.env.example` to `.env.local` and supply your configuration. Never commit
`.env.local`. Vite exposes `VITE_` values to the browser: use only a public
Supabase anon/publishable key, never a service-role key.

## How slot availability works

The home page fetches slots from `VITE_SLOTS_WEBHOOK_URL` with a selected
`date=YYYY-MM-DD`. It refreshes approximately every 30 seconds while visible.
It reads the current user's upcoming bookings from Supabase and blocks additional
bookings until existing appointments end or are cancelled. Times use Asia/Karachi.

Booking and cancellation POST to `VITE_BOOK_SLOT_WEBHOOK_URL` and
`VITE_CANCEL_SLOT_WEBHOOK_URL`. Both send date, start/end time, and user ID;
booking also sends email and full name. Cancellation requires a JSON response
of `{ "success": true }`. Calendar events, Meet invitations, and reminders are
configured in external n8n workflows; workflow exports are not included here.

## Prototype limitations

Server-side login-token verification, Calendar conflict handling, and complete
partial-failure recovery remain unfinished. Final end-to-end testing is pending.
See `supabase/BOOKING-LIMITS.md` for database setup and verification.

## Checks and hosting

Run `npm run build`, `npm run lint`, and `node --test src/lib/bookingRules.test.js`.
Pushing to GitHub stores the source; it does not automatically host the app.
Hosting requires serving `dist` with SPA fallback to `index.html`, deployment
environment variables, and updated n8n allowed origins and Supabase redirect URLs.

## Run it

```bash
npm install
npm run dev
```

Open the printed local URL. You'll land on `/login`; use **Create one** to
sign up. The first time you sign in, you'll be asked for your full name and
phone number (stored in the `users` table) before the time slots page
appears — returning users skip straight to it. Pick any open slot to book
it; booked slots show as reserved for everyone else and can be cancelled by
the person who booked them.
